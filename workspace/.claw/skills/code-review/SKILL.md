# 代码审查 SOP

1. 收到审查请求后，先使用 `read_file` 读取所有待审查的源文件，理解代码整体结构。
2. 重点关注以下维度：
   - **正确性**：逻辑是否有缺陷，边界条件是否处理。
   - **可读性**：命名是否清晰，是否有不必要的复杂抽象。
   - **安全性**：是否存在路径遍历、SQL 注入、敏感信息泄露等风险。
   - **健壮性**：异常处理是否完善，是否存在潜在的 NPE 或资源泄漏。
3. 审查结果必须以 Markdown 格式输出，按严重程度从高到低排列。
4. 每个问题必须附带具体的修改建议和代码示例。
5. 禁止只泛泛地说"代码可读性不好"这种缺乏建设性的废话。
